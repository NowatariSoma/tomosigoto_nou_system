# モバイル参謀プロジェクトルール

## 概要
このドキュメントでは、モバイル参謀プロジェクトにおけるチケット管理やフォルダ構造のルールを定義しています。すべての開発者はこれらのルールに従って作業を行ってください。

## チケット命名規則

**形式**: `[エリア]-[機能]-[連番](.サブタスク番号)`

**エリアコード**:
- `BACK` - バックエンド
- `FRONT` - フロントエンド
- `AI` - AI/ML関連
- `QA` - テスト・品質保証
- `OPS` - デプロイ・運用

## フォルダ構造ルール

```
tickets/
  ├── [エリア]/
  │   └── [チケットID]/
  │       ├── README.md                  # チケット概要
  │       ├── [チケットID.サブタスク番号]/  # サブタスク専用フォルダ
  │       │   ├── README.md              # サブタスク概要
  │       │   └── [関連ファイル]          # サブタスク固有ファイル
  │       └── [関連ファイル]              # メインチケット関連ファイル
```

## 必須ルール

1. すべてのチケットは専用フォルダを持つこと
2. すべてのサブタスクは専用サブフォルダを持つこと
3. すべてのチケット・サブタスクフォルダにはREADME.mdを作成すること
4. ファイルは関連性の高い最も適切なチケットフォルダに配置すること
5. 複数サブタスク共有リソースはメインチケットフォルダに配置すること

## 技術スタック規則

### 認証システム (Supabase)
1. 認証機能は必ずSupabaseを利用して実装すること
2. 環境変数管理を徹底し、秘密鍵は`.env`ファイルで管理すること
3. Supabase依存はinfrastructure層のみに制限すること
4. JWTトークンの有効期限設定は1時間を標準とすること
5. リフレッシュトークンは安全に保管し、有効期限は7日間を標準とすること
6. 開発環境と本番環境で別のSupabaseプロジェクトを使用すること
7. Supabaseのセキュリティルール（RLS）を適切に設定すること
8. 認証関連のエラーメッセージは詳細を隠蔽し、一般的な表現とすること

### アーキテクチャ規則
1. ドメイン駆動設計（DDD）の原則に従うこと
2. レイヤー間の依存関係は内側に向かうこと（依存性逆転の原則）
3. 外部サービス（Supabase等）への依存はinfrastructure層に閉じ込めること
4. ビジネスロジックはドメイン層とアプリケーション層に配置すること
5. インターフェース層は外部からのリクエストの受付と結果の返却のみを担当すること

## レイヤー構成
各コンテキストは以下の4つのレイヤーで構成されています：

1. `domain`: ビジネスロジックとエンティティ
2. `application`: ユースケースとアプリケーションサービス
3. `infrastructure`: 技術的な実装の詳細
4. `interfaces`: APIエンドポイントとプレゼンテーション層

## ドキュメントタイプ別テンプレート

### 設計ドキュメント
- タイトル: システム/コンポーネント名
- セクション: 概要、システム構成、コンポーネント詳細、データフロー、非機能要件、拡張性

### 実装ガイド
- タイトル: コンポーネント/機能名
- セクション: 概要、前提条件、基本的な使い方、ユースケース、エラーハンドリング、最適化、FAQ

### テスト計画
- タイトル: コンポーネント/機能名
- セクション: テスト概要、環境、テストケース、結果サマリー、発見された問題、結論

### API仕様書
- タイトル: API名
- セクション: 概要、ベースURL、認証、エンドポイント（リクエスト/レスポンス）、エラーコード、例

## チケット管理プロセス

1. 新チケットは適切なディレクトリに追加
2. チケットには詳細な仕様、受け入れ基準、関連資料を記載
3. チケット一覧（tickets.md）にエントリを追加
4. スプリント計画に組み込む 
5. 実行方法を明確に記載する（環境構築手順、コマンド、必要なパラメータなど） 

## コーディング規則

### Python
1. PEP 8スタイルガイドに従うこと
2. 型ヒント（Type Hints）を使用すること
3. ドキュメンテーションコメントはGoogle Styleで記述すること
4. 関数やクラスには適切なドキュメントコメントを付与すること
5. 例外処理は適切に行い、カスタム例外を定義すること
6. 非同期処理はasync/awaitを使用すること
7. 環境変数は適切に管理し、秘密情報をハードコードしないこと

### 認証関連
1. パスワードの検証は最低限8文字以上で英数字記号を含むことを確認すること
2. ログイン失敗回数に制限を設けること（5回以上の失敗で一時的にロック等）
3. セッション管理はユーザーのIPアドレスとデバイス情報を記録すること
4. トークンはHTTPSでのみ送信すること
5. セキュリティに関わるログは詳細に記録すること（ただし個人情報は適切に保護）
