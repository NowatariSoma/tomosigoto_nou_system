## 概要
このディレクトリは練習表自動生成システムの開発チケットを管理します。各チケットはエピック（大分類）ごとにフォルダに整理され、詳細な作業内容、依存関係、成果物などを定義しています。

## チケット管理ルール

### チケット命名規則
チケットIDは以下の形式で命名されています：
```
[カテゴリ]-[機能]-[連番]
```

例：
- BACK-DB-001: バックエンド - データベース - 001番
- ALGO-SCHED-001: アルゴリズム - スケジューリング - 001番
- FRONT-ARCH-001: フロントエンド - アーキテクチャ - 001番

### ステータス管理
各チケットには以下のステータスがあります：
- 未開始: 作業が開始されていない
- 進行中: 現在作業中
- レビュー中: レビュー待ち
- 完了: 作業完了

### 依存関係
チケット間の依存関係は各チケットのREADME内に明記されています。依存するチケットが完了するまで作業を開始しないでください。

### フォルダ構造
各チケットフォルダには以下の構造があります：
```
tickets/
├── [エピック]/
│   ├── [チケットID]/
│   │   ├── README.md      # チケット概要
│   │   ├── docs/          # 関連ドキュメント
│   │   ├── assets/        # 画像などのアセット
│   │   └── work/          # 作業成果物
│   └── ...
└── ...
```

### 新規チケット作成
新規チケットを作成する場合は、既存の類似チケットをテンプレートとして使用し、適切なエピックフォルダに配置してください。

## チケット更新ワークフロー
1. 担当者がチケットを選択し、ステータスを「進行中」に更新
2. 作業完了後、成果物をチケットフォルダにコミット
3. ステータスを「レビュー中」に更新
4. レビュー完了後、ステータスを「完了」に更新

## 設計書参照
各チケットには関連する設計書へのリンクが含まれています。詳細な仕様については設計書を参照してください。

## チケット命名規則

チケットIDは以下の形式で命名されています：

`[エリア]-[機能]-[連番](.サブタスク番号)`

例：
- `BACK-DB-001` - バックエンド・データベース関連の最初のメインチケット
- `BACK-DB-001.1` - 上記チケットの最初のサブタスク

### エリアコード

- `BACK` - バックエンド
- `FRONT` - フロントエンド
- `AI` - AI/ML関連
- `QA` - テスト・品質保証
- `OPS` - デプロイ・運用

### チケットファイル構成

チケットは以下のファイル構成で管理されています：

- `tickets/` - チケットファイルが保存されるディレクトリ
  - `backend/` - バックエンド関連チケット
  - `frontend/` - フロントエンド関連チケット
  - `ai/` - AI/ML関連チケット
  - `qa/` - テスト・品質保証関連チケット
  - `ops/` - デプロイ・運用関連チケット

## フォルダ管理ガイドライン

チケットごとに専用のフォルダを作成し、関連するドキュメントやコードを管理します。

### フォルダ構造

```
tickets/
  ├── [エリア]/
  │   ├── [チケットID]/
  │   │   ├── README.md                  # チケット概要と構成の説明
  │   │   ├── [チケットID.サブタスク番号]/  # サブタスク専用フォルダ
  │   │   │   ├── README.md              # サブタスク概要と詳細
  │   │   │   └── [関連ファイル]          # サブタスク固有のファイル
  │   │   └── [関連ファイル]              # メインチケットに関連するファイル
```

### フォルダ管理のベストプラクティス

1. **専用フォルダの作成**
   - 各メインチケットは固有のフォルダを持ちます
   - サブタスクも固有のサブフォルダを持ちます

2. **ファイルの配置**
   - チケットに固有のドキュメントやコードはそのチケットのフォルダに配置します
   - サブタスク固有のファイルはサブタスクのフォルダに配置します
   - 複数のサブタスクで共有されるリソースはメインチケットのフォルダに配置します

3. **READMEファイルの作成**
   - 各チケットフォルダには必ずREADME.mdを作成し、フォルダの内容と構成を説明します
   - READMEには関連するすべてのファイルとその目的を記載します

4. **適切な分類**
   - 資料やコードはその内容に最も関連性の高いチケットフォルダに分類します
   - 重複を避け、必要に応じてリンクを使用して関連資料を参照します
