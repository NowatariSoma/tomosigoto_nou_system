# 実装指針：セキュリティ対策

## 1. 概要

本ドキュメントでは、練習表自動生成システムのセキュリティ対策に関する指針を説明します。システムの安全性、データの機密性・完全性・可用性を確保するための方針と実装手法を定義します。

## 2. セキュリティ設計原則

- **最小権限の原則**: 必要最小限の権限のみを付与
- **多層防御**: 複数の防御層によるセキュリティ強化
- **セキュアバイデザイン**: 設計段階からセキュリティを考慮
- **失敗安全**: エラー発生時も安全な状態を維持
- **監査と追跡**: すべての重要な操作を記録

## 3. 認証と認可

### 3.1 認証方式

- **JWT認証**: アクセストークンとリフレッシュトークンの使用
- **多要素認証（MFA）**: 重要な操作に対して追加の認証要素を要求
- **パスワードポリシー**: 強固なパスワード要件の適用

### 3.2 認可モデル

- **ロールベースアクセス制御（RBAC）**:
  - システム管理者: すべての機能にアクセス可能
  - コーチ: チームと練習表の管理
  - プレイヤー: 割り当てられた練習表の閲覧

### 3.3 実装例

```typescript
// auth.guard.ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private jwtService: JwtService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const token = this.extractTokenFromHeader(request);
    
    if (!token) {
      throw new UnauthorizedException('認証トークンがありません');
    }
    
    try {
      const payload = await this.jwtService.verifyAsync(token, {
        secret: process.env.JWT_SECRET
      });
      
      // リクエストにユーザー情報を添付
      request['user'] = payload;
    } catch {
      throw new UnauthorizedException('無効な認証トークンです');
    }
    
    return true;
  }

  private extractTokenFromHeader(request: Request): string | undefined {
    const [type, token] = request.headers.authorization?.split(' ') ?? [];
    return type === 'Bearer' ? token : undefined;
  }
}

// roles.guard.ts
import { Injectable, CanActivate, ExecutionContext, ForbiddenException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { UserRole } from '../enums/user-role.enum';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<UserRole[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);
    
    if (!requiredRoles) {
      return true;
    }
    
    const { user } = context.switchToHttp().getRequest();
    
    if (!user || !user.roles) {
      throw new ForbiddenException('権限がありません');
    }
    
    const hasRequiredRole = requiredRoles.some(role => 
      user.roles.includes(role)
    );
    
    if (!hasRequiredRole) {
      throw new ForbiddenException('この操作を行う権限がありません');
    }
    
    return true;
  }
}
```

## 4. 入力検証とサニタイズ

### 4.1 フロントエンド検証

- **リアルタイムバリデーション**: ユーザー入力時のフィードバック提供
- **フォーム検証ライブラリ**: Zod, Yup などを使用した型安全な検証

### 4.2 バックエンド検証

- **スキーマベース検証**: Class-validatorなどによるDTOの検証
- **ホワイトリスト方式**: 許可された入力のみを受け付け

### 4.3 実装例

```typescript
// create-schedule.dto.ts
import { IsDateString, IsString, IsNotEmpty, Matches, Length, IsOptional } from 'class-validator';
import { Transform } from 'class-transformer';

export class CreateScheduleDto {
  @IsNotEmpty({ message: 'チームIDは必須です' })
  @IsString()
  teamId: string;

  @IsNotEmpty({ message: '練習日は必須です' })
  @IsDateString()
  practiceDate: Date;

  @IsNotEmpty({ message: '開始時間は必須です' })
  @Matches(/^([01]\d|2[0-3]):([0-5]\d)$/, { 
    message: '開始時間は HH:MM 形式で入力してください' 
  })
  startTime: string;

  @IsNotEmpty({ message: '終了時間は必須です' })
  @Matches(/^([01]\d|2[0-3]):([0-5]\d)$/, { 
    message: '終了時間は HH:MM 形式で入力してください' 
  })
  endTime: string;

  @IsNotEmpty({ message: '場所は必須です' })
  @Length(1, 100, { message: '場所は1〜100文字で入力してください' })
  @Transform(({ value }) => value.trim())
  location: string;

  @IsOptional()
  @Length(0, 1000, { message: '備考は1000文字以内で入力してください' })
  @Transform(({ value }) => value ? value.trim() : '')
  notes?: string;
}

// ValidationPipe の設定 (main.ts)
import { ValidationPipe } from '@nestjs/common';

app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true, // DTOに定義されていないプロパティを除去
    forbidNonWhitelisted: true, // 定義外のプロパティがあるとエラー
    transform: true, // 型変換を自動実行
    transformOptions: {
      enableImplicitConversion: false, // 明示的な変換のみ許可
    },
  }),
);
```

## 5. データセキュリティ

### 5.1 保存データの保護

- **データベース暗号化**: 保存時の暗号化（RDS暗号化）
- **機密データの暗号化**: パスワードのハッシュ化、個人情報の暗号化
- **バックアップ暗号化**: すべてのバックアップの暗号化

### 5.2 転送中データの保護

- **HTTPS通信**: すべての通信をTLS 1.2以上で保護
- **APIエンドポイント保護**: CORS設定の厳格化
- **安全なWebSocket**: 認証済みWebSocket接続

### 5.3 実装例

```typescript
// パスワードハッシュ化 (user.service.ts)
import * as bcrypt from 'bcrypt';

async register(userData: RegisterUserDto): Promise<User> {
  // パスワードをハッシュ化
  const hashedPassword = await bcrypt.hash(userData.password, 12);
  
  // ハッシュ化したパスワードでユーザーを作成
  const newUser = this.userRepository.create({
    ...userData,
    password: hashedPassword,
  });
  
  return this.userRepository.save(newUser);
}

// CORSの設定 (main.ts)
app.enableCors({
  origin: process.env.ALLOWED_ORIGINS.split(','),
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
  allowedHeaders: ['Content-Type', 'Authorization'],
  credentials: true,
  maxAge: 86400,
});
```

## 6. Web アプリケーションセキュリティ

### 6.1 一般的な脆弱性対策

| 脆弱性 | 対策 |
|-------|------|
| XSS攻撃 | コンテンツセキュリティポリシー(CSP), 出力エスケープ |
| CSRF攻撃 | CSRFトークン, SameSite Cookie |
| SQLインジェクション | パラメータ化クエリ, ORM |
| DoS攻撃 | レートリミット, WAF |
| クリックジャッキング | X-Frame-Options ヘッダー |

### 6.2 セキュリティヘッダー

```typescript
// security middleware (main.ts)
import helmet from 'helmet';

app.use(helmet());
app.use(helmet.contentSecurityPolicy({
  directives: {
    defaultSrc: ["'self'"],
    scriptSrc: ["'self'", "'unsafe-inline'"],
    styleSrc: ["'self'", "'unsafe-inline'"],
    imgSrc: ["'self'", 'data:'],
    connectSrc: ["'self'", 'https://api.example.com'],
    fontSrc: ["'self'"],
    objectSrc: ["'none'"],
    mediaSrc: ["'self'"],
    frameSrc: ["'none'"],
  },
}));
app.use(helmet.referrerPolicy({ policy: 'same-origin' }));
```

### 6.3 レートリミット

```typescript
// rate-limit.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import rateLimit from 'express-rate-limit';

@Injectable()
export class RateLimitMiddleware implements NestMiddleware {
  private limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15分間
    max: 100, // IPあたり100リクエストまで
    standardHeaders: true,
    legacyHeaders: false,
    message: 'リクエスト数が多すぎます。しばらく経ってから再試行してください。',
  });

  use(req: Request, res: Response, next: NextFunction) {
    this.limiter(req, res, next);
  }
}
```

## 7. インフラストラクチャセキュリティ

### 7.1 ネットワークセキュリティ

- **ネットワーク分離**: VPC、サブネット、セキュリティグループの適切な設計
- **WAF設定**: WebアプリケーションファイアウォールによるL7防御
- **DDoS対策**: AWS Shield、CloudFrontなどの活用

### 7.2 サーバーセキュリティ

- **OS強化**: 最小限のサービス実行、不要なパッケージの削除
- **コンテナセキュリティ**: 最小権限、読み取り専用ファイルシステム
- **定期的な脆弱性スキャン**: 自動スキャンと修正

### 7.3 アクセス管理

- **IAM設定**: 最小権限の原則に基づく権限設定
- **セキュアな認証情報管理**: AWS Secrets Manager、環境変数の適切な扱い
- **インフラアクセス監査**: CloudTrailによる監査ログの記録

## 8. セキュリティ監視と対応

### 8.1 ログ監視

- **集中ログ管理**: CloudWatch Logs、Elasticsearch
- **セキュリティイベントの監視**: 不審なアクセスパターンの検出
- **アラート設定**: 異常な動作に対する通知

### 8.2 インシデント対応

1. **検知**: セキュリティイベントの検知
2. **封じ込め**: 被害拡大防止策の実施
3. **排除**: 脆弱性の修正、侵入経路の遮断
4. **復旧**: 安全な状態への回復
5. **学習**: 事後分析と再発防止策の実施

### 8.3 セキュリティ評価

- **定期的な脆弱性スキャン**: 自動化されたセキュリティテスト
- **ペネトレーションテスト**: 外部専門家による侵入テスト
- **コードセキュリティレビュー**: セキュリティの観点からのコードレビュー

## 9. セキュリティコンプライアンス

- **個人情報保護**: GDPR、個人情報保護法などへの対応
- **業界標準**: OWASP Top 10対策
- **セキュリティポリシー**: 組織のセキュリティポリシーへの準拠

## 10. まとめ

本ドキュメントで説明したセキュリティ対策を実装することで、以下の目標を達成します：

1. **安全な認証・認可**: 適切なアクセス制御によるデータ保護
2. **脆弱性対策**: 一般的なWeb脆弱性からの防御
3. **データ保護**: 保存データと転送中データの機密性保護
4. **インフラストラクチャ防御**: ネットワークとサーバーレベルでの防御
5. **継続的なセキュリティ管理**: 監視、対応、評価の継続的実施

セキュリティは継続的なプロセスであり、新たな脅威や脆弱性に対応するため、本ドキュメントを定期的に見直し、更新してください。
