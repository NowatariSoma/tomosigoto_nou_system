# 練習表自動生成システム 設計書

## 概要
このリポジトリには、同志社大学能部の練習表自動生成システムに関する設計書が含まれています。本システムは練習表作成業務の効率化、練習機会の公平性向上、練習の質の向上を目的としています。

## 主な課題と目標
現状の課題：
- 練習表の手動作成に多大な時間を要し、担当者・部長に負荷が集中
- 直前欠席への対応が困難で、練習の質のばらつきや練習機会の逸失が発生
- 練習表の共有遅延による部員への周知の遅れ
- 公平な監督者ローテーションの保証不足
- 権限管理の曖昧さによる無許可変更リスク

設定目標：
- 練習表作成・再生成時間を「秒〜数分」に短縮し、即時共有を可能に
- 欠席情報を反映した自動リスケジュールによる練習機会の公平性確保
- アルゴリズムによる監督者ローテーションの最適化
- 閲覧／編集権限の分離と変更履歴・バージョン管理の実装

## 設計思想
本システムはドメイン駆動設計（DDD）の思想に基づいて設計されています。これにより、以下の利点があります：
- ユビキタス言語の確立による要件誤解の減少
- バウンデッドコンテキストによる責務の明確化
- ドメインモデル内でのビジネスルールのカプセル化
- テスト容易性の向上
- 拡張性と保守性の確保

## 設計書の構成
設計書は以下のセクションで構成されています：

1. **概要** - システムの目的、設計思想、全体像
2. **ドメインモデル** - エンティティ、値オブジェクト、集約と不変条件
3. **バウンデッドコンテキスト** - コンテキストマップ、各コンテキストの責務、連携
4. **ドメインサービス** - 各ドメインサービスの責務、インターフェース定義
5. **アプリケーション層** - ユースケース設計、各ユースケースの流れ、サービス間連携
6. **インターフェース設計** - API設計、画面遷移図、主要画面概要
7. **権限・ロール設計** - ロール定義、権限マトリクス、アクセス制御
8. **非機能要件対応** - パフォーマンス、セキュリティ、可用性・スケーラビリティ
9. **アルゴリズム詳細** - スケジュール生成アルゴリズム、監督者割当アルゴリズム、最適化戦略
10. **データモデル** - 論理データモデル、整合性制約
11. **設計モデル詳細** - UMLモデル、ER図、画面設計、アーキテクチャモデル、実装指針
12. **テスト戦略と計画** - テスト戦略の概要、テストレベル、テスト種類、テスト環境、テスト自動化、不具合管理
13. **設計書運用と保守** - 設計書管理の基本方針、更新管理プロセス、ドキュメント品質基準

## 利用方法
各設計書は関連するMarkdownファイルに記載されています。設計書間の関連性を理解するために、まず[概要](./01_概要.md)および[目次](./00_設計書_目次.md)から閲覧することをお勧めします。

## システム全体アーキテクチャ
本システムはクリーンアーキテクチャを採用し、以下の層で構成されています：
- ユーザーインターフェース層
- API層
- アプリケーション層
- ドメイン層
- インフラストラクチャ層

## ステークホルダー
システムの主なステークホルダーは以下の通りです：
- 部長 (ClubCaptain) - Admin権限
- 作成担当 (Scheduler) - Editor権限
- 部員 (Member) - Viewer / AbsenceReporter権限
- システム管理者 (ITAdmin) - SysAdmin権限
